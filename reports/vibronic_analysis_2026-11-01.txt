Vibronic analysis implementation and validation — 2026-11-01

Scope
Added UV-Vis > Vibronic analysis, opening an independent window resizable in
both dimensions. It can open before any TD-DFT output is loaded, retain results
when closed, and reopen from the same button. All implementation is in named
files under src/vibronic; mod.rs contains declarations/reexports only.

Implemented calculations
- Franck–Condon mode activities from a ground-state Hessian and an excited-state
  gradient evaluated at that same geometry: projected gradients, dimensionless
  displacements, Huang–Rhys factors and reorganisation energies.
- Relative resonance-Raman mode intensities in Behemoth's short-time approximation.
- Zero-temperature absorption band from independent displaced harmonic oscillators,
  using the ground-state frequencies. Vertical energy, grid spacing and maximum
  quanta per mode are configurable. A loaded UV-Vis root can supply the energy
  through an explicit selection. The gradient must belong to that chosen state.
- Duschinsky rotation J and dimensionless displacement K from two Hessians, with
  mass-weighted alignment, mode correspondences, overlaps and participation ratios.
- Interactive plots for Raman activities, Huang–Rhys factors and the absorption
  band, plus a J-squared heat map with numerical hover readouts.
- Copy data / Save data export provenance, mode tables, the complete signed J
  matrix and K, and absorption-bin probabilities where available.

Inputs and safeguards
ORCA .hess retains its geometry and isotope masses. A geometry-free Turbomole
$hessian requires a matching single-frame XYZ in Angstrom. Gradient inputs accept
ORCA .engrad and single-cycle Turbomole $grad, including Fortran D exponents.
Gradient coordinates must match the Hessian after rigid mass-weighted alignment;
the gradient is rotated into that frame as well. Atom order and, for two Hessians,
isotope masses must agree. Dummy atoms are rejected for existing Hessians: removing
rows/atoms would invalidate the supplied Hessian correspondence.

Translations/rotations are projected out. Imaginary modes are excluded with an
explicit warning; the positive-frequency cutoff defaults to zero. Large residual
gradient components are reported. Invalid files/errors appear in the existing
copyable error popup. The calculation runs off the UI thread and preserves the
previous result if a new analysis fails.

Band generation refuses oversized grids/work estimates and rejects a quantum
cutoff retaining less than 99.9% of the joint population, instead of silently
renormalising a substantially truncated progression. If the band fails, the
valid mode activities remain available and the reason appears in a popup.

Behemoth itself was not edited during this task.

The imported Duschinsky alignment originally used power iteration starting with
quaternion (1,0,0,0). For an exact half-turn this seed can be orthogonal to the
largest eigenvector. Beavyr's existing symmetric eigensolver now solves all four
quaternion eigenvectors; the largest eigenvalue supplies the rotation. An exact
180-degree rotation plus translation is covered by a regression test checking
both aligned coordinates and gradient components. The J/K equations are unchanged.
Additional validation guards protect invalid indices, masses and nonfinite data.

Existing FeAcac3 exploratory/ignored tests and their old helper implementation
were preserved in test-only legacy.rs; production uses the imported implementation.
No dependencies were added, and no changes were committed.

Model limits
Raman values are relative activities, not absolute cross-sections or a
laser-frequency-dependent resonance model. The absorption band has no hot bands,
Herzberg–Teller term, Duschinsky mixing or excited-state frequency changes.
Duschinsky analysis is a separate diagnostic, not an assertion that those effects
have been included in the plotted absorption band. Inputs are supplied by the
user; this window does not launch new excited-state gradient/Hessian calculations.
