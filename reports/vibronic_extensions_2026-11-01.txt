Beavyr vibronic extensions — implementation and validation
2026-11-01

Scope
Implemented the five requested additions in order in Beavyr. Behemoth was
inspected and used as a reference; no Behemoth files were changed. No commits,
pushes, dependency additions, MPI changes or Python-environment changes were made.
Compilation and test processes were restricted to CPU cores 0–3, Cargo -j4.


Overview and location
Open UV-Vis -> Vibronic analysis -> Vibronic spectra. The five additions are:
1. Absorption from two harmonic surfaces, including thermal hot bands.
2. Fluorescence from the emitting state's thermal population.
3. Laser-dependent resonance Raman with fundamentals and second-order bands.
4. Herzberg-Teller transition-dipole contributions and FC/HT interference.
5. Mode animation, experimental overlays, explicit shifts, and data/figure export.
The existing gradient-based activity analysis and Duschinsky diagnostics remain
separate choices. The new spectral methods do not replace those quick analyses.

How to run an analysis
1. Select the ground- and excited-state Hessians. If a Hessian lacks geometry,
   provide its matching XYZ file. Both states must use the same atom order and
   masses. The full two-Hessian calculation requires stable minima.
2. Choose Absorption, Fluorescence or Resonance Raman, and Beavyr or ORCA ESD.
3. Enter E(excited minimum) - E(ground minimum), in eV, WITHOUT ZPE. The code
   supplies the zero-point correction from the Hessians. A vertical excitation
   energy at the ground geometry is not this minimum-to-minimum gap.
4. Set temperature, spectral spacing and Lorentzian/Gaussian FWHM. For Raman,
   use 0 K, enter laser wavelengths in nm (for example: 532, 500), choose the
   final-state order, and set the separate Raman linewidth.
5. For internal Condon Raman, provide a transition-dipole vector or obtain it
   through the property-file/PySCF/Psi4 choices. For Herzberg-Teller, enable its
   checkbox and provide derivatives through a property file or Python backend.
   A manually entered constant vector alone is insufficient for this option.
6. For PySCF/Psi4 collection, select the saved interpreter/activation settings,
   HF or DFT reference, functional where applicable, basis, charge, multiplicity,
   root, number of roots and TDA/full-response choice. These settings should be
   consistent with the electronic state and model used for the supplied Hessians.
   For ORCA, select its executable and electronic settings; ORCA collects its
   own transition properties and performs native ESD calculations.
7. Click Analyse. Cancel stops the job. Errors use the copyable warning window.
8. Use Copy data or Save data for the original results and calculation metadata.
   Load spectrum imports experimental two-column data; select its units first.
   Copy displayed data / Save displayed data include the displayed shift and
   normalisation. Save figure writes SVG. Animate mode selects a ground- or
   excited-state mode; Stop or closing the analysis window restores equilibrium.

Required information by method
- Full absorption/fluorescence: both Hessians and geometries, minimum electronic
  energy gap, temperature and spectral-grid/broadening settings.
- Internal Raman: those inputs, laser wavelengths, final-state order, and an
  electronic transition-dipole vector; temperature is restricted to 0 K.
- Internal Herzberg-Teller: transition dipole plus its Cartesian derivatives,
  or backend settings sufficient to calculate them. Property coordinates are
  in bohr, dipoles in e*bohr, derivatives in e, with 3N derivative rows.
- Experimental comparison: a separate two-column spectrum and its x-axis units.

1. Full harmonic absorption
Two-Hessian Gaussian time correlation with Duschinsky rotation, displacement,
frequency changes and finite-temperature initial populations, followed by FFT.
The user supplies the electronic minimum-to-minimum gap; ZPE is obtained from
the Hessians. An optional photon-energy prefactor produces a relative optical
spectrum. Stable minima with matching atoms, masses and mode counts are required.
No truncated enumeration of intermediate vibrational states is used.

2. Fluorescence
Reverse the initial/final harmonic surfaces and displacements, populate the
emitting state's modes, reverse the photon-energy axis, and optionally apply
E^3. Linear dipoles are transformed into the reversed coordinate frame.
Internal optical profiles are area-normalised; no absolute radiative lifetime
is inferred from a broadened, finite spectral window.

3. Resonance Raman
Resonant Kramers–Heisenberg time integration of Gaussian polynomial moments.
Selectable laser wavelengths, lifetime/disorder broadening, fundamentals and
first overtones/combination bands. Final-state line broadening is independent
of the intermediate-state damping. Tensor invariants supply orientationally
averaged scattering factors; an optional scattered-photon frequency^4 factor
is available. Nested quadrature checks integration error. The implementation
uses one intermediate electronic state, the resonant term and a 0 K initial
vibrational ground state; it is not a multistate or finite-temperature Raman
implementation. Exported line strengths retain relative weights across lasers.

4. Herzberg–Teller
Linear transition dipoles are included inside the harmonic correlation and
Raman tensor amplitudes. FC/HT interference is retained before squaring.
Property-file import validates atom order, coordinates, units and finite data.
A template contains NaN placeholders so unfilled derivatives cannot silently
be accepted as zeros. Derivatives are projected as sum_i L_ik d(mu)/dx_i,
following Behemoth's normal-mode projection convention.

Automatic HF/DFT-reference collection uses PySCF or Psi4 in the user's saved
Python environment. Central Cartesian finite differences use overlap-based
state selection and phase alignment, adapted from Behemoth's biorthogonal
occupied/virtual state-overlap construction. TDDFT tracking uses normalized
X pseudo-CI amplitudes; it is not an exact many-electron TDDFT wavefunction.
Weak or ambiguous matches are rejected, with tracking.csv and calculation logs
retained. The derivative expansion is referenced to the ground Hessian geometry
and Cartesian frame. This differs from some native ORCA expansion conventions.
The finite-difference step is adjustable; difficult states still require step
convergence checks and inspection of electronic-state character.

Behemoth inspection
- src/normalmode/vibronic/herzberg_teller.rs: supplied Cartesian derivative
  projection and mode activities, but not a complete automatic derivative job.
- src/hamiltonian/tddft/state_overlap.rs: cross-geometry state-overlap machinery.
- TDDFT and sTDDFT types/solvers: transition-dipole vectors already available.
- src/utils/cli/excited_state_derivatives.rs: energy/nuclear-gradient driver,
  not a transition-dipole derivative exporter with tracked phases.
Automatic Behemoth property collection was not added. Behemoth and other
programs can supply data through the validated property-file route.

5. Results and visualization
Resizable UV-Vis analysis window; ground/excited normal-mode animation with
looping vibration playback and equilibrium restoration when closed/stopped.
A subsequently loaded unrelated trajectory is not overwritten on closure.
Experimental two-column spectrum import (eV, cm^-1 or nm), explicit calculated
energy shift, peak normalisation, numerical hover values, SVG export, and
copy/save of displayed data. Raman defaults to a shift axis in cm^-1.
Raw data and calculation metadata remain separately exportable. Axis conversion
preserves sampled intensity values, not densities per unit energy/wavelength.

ORCA integration
Uses only the selected executable, an input file, and captured output. Native
ESD(ABS), ESD(FLUOR), ESD(RR), DOHT, two Hessians, Cartesian modes and Duschinsky
mixing. Both normal ORCA termination and successful ESD completion are checked.
Actual testing established UNIT WN, Lorentzian HWHM=FWHM/2 and Gaussian
sigma=FWHM/sqrt(8 ln 2). Pure Lorentzian broadening must select LORENTZ rather
than VOIGT with zero Gaussian width. RRSLINEW=10 was verified to give ~10 cm^-1
FWHM. Multiple lasers produce separate .spectrum.<rounded wavenumber> files;
missing/colliding output files are detected rather than silently omitted.
Cancellation terminates the child process tree and cancelled results are not
applied. Successful and failed work directories are retained for inspection.

Implementation map
All implementation files are under src/vibronic/ unless otherwise noted:
- harmonic_model.rs: two-surface model, mode mapping and reversal.
- gaussian_correlation.rs, complex_math.rs, thermal_spectrum.rs: Gaussian
  correlation, complex linear algebra and Fourier spectrum assembly.
- optical_spectrum.rs: absorption/emission axes and optical prefactors.
- raman_spectrum.rs: resonant Raman amplitudes, tensors and line profiles.
- transition_properties.rs: property parsing, projection and Gaussian moments.
- property_job.rs, transition_driver.py: Python property jobs and state tracking.
- orca_esd.rs, process.rs: native ORCA input/output and cancellable child jobs.
- spectral_job.rs, spectral_controls.rs: job dispatch and calculation settings.
- spectrum_view.rs, mode_animation.rs: plotting, overlays, exports and animation.
- harmonic_tests.rs, extensions_tests.rs, transition_driver_tests.py: new tests.
- Existing analysis.rs, state.rs and ui.rs connect the new features; src/ui.rs
  applies animation requests to the viewer. mod.rs contains declarations only.
- README.md documents entry points and supported workflows.

Limits and remaining review
- The surfaces and normal modes are harmonic; anharmonic effects are not added.
- Internal optical spectra are relative, not absolute radiative rates/lifetimes.
- Raman is resonant, single-intermediate-state and 0 K, with final total quantum
  number at most two. Finite-temperature/multistate Raman is not implemented.
- Automatic property collection is for PySCF/Psi4 HF/DFT references. Other
  backends require supplied property data, except ORCA's native ESD route.
- Near-degenerate states can fail the overlap criterion. Such failure is explicit;
  it is not silently handled by changing roots or inventing derivatives.
- Python property expansion uses the ground Hessian reference frame. Native
  ORCA follows its own ESD conventions, so identical HT spectra across routes
  are not claimed for arbitrary geometries and electronic settings.
- Input linewidths, finite-difference steps and spectral grids still need suitable
  choices for the molecule; successful execution is not proof of model accuracy.
- Interactive visual review and validation on representative physical excited
  states remain necessary before a release-readiness claim.
