Controls and legends
--------------------
Surface isovalue, opacity and resolution have aligned labels/numeric fields.
Atomic-property windows use the same compact row layout. Method and tracking
explanations are collapsed initially; active display controls remain visible.
Legends are optional overlays, with the same range for every frame in a result.
Automatic ranges use all frames; custom ranges are entered in displayed units.
Polarizability is sequential, signed Fukui/reactivity is diverging through neutral.
Colour changes apply to halo rendering and animation-export snapshots. Atomic
halo radius still uses cube-root magnitude. Density/orbital lobe colours remain
user selectable. Viewer legend overlays are not included in exported animations.

Calculation queue / resume
--------------------------
Progress shows completed, remaining and active source frames; elapsed time and
estimated remaining duration. Resume uses the saved input plan, not current UI
settings. New jobs save the complete selected geometry list and engine settings
before starting. Completed wavefunctions are checked for geometry and file checksum.
The input plan also has a checksum to detect accidental changes. These FNV-1a
checksums detect corruption/edits; they are not authentication signatures.
An OS file lock prevents concurrent workers writing the same calculation folder.
Interrupted/failed frame directories are retained; retries use new numbered folders.
Completed wavefunctions are reused unchanged. Native program installations and
shell/environment setup are untouched. Older calculations lacking a saved input
plan cannot be resumed. Changing saved executable paths/settings requires a new
calculation rather than silently mixing results.

Plots
-----
Shared styling/export is used by atomic-polarizability, reactivity, trajectory-series
and scan-energy plots. Appearance controls start collapsed. SVG is vector output;
PNG uses the existing Bevy image encoder and bundled font. Both are rendered from
the same plot primitives used on screen. Export uses a white background, chosen
font/line/marker settings and dimensions, and retains axis units and scan reference
energy/point. Data order and missing-value gaps are preserved. Hover/click uses the
original source point on reversed scans. Spectrum/histogram renderers are unchanged.

Orbital tracking
----------------
Opt-in tracking starts from one selected orbital at a chosen anchor frame and
walks adjacent geometries in both directions. Same-spin candidates are ranked by
normalized |C_i(A)^T S(A,B) C_j(B)|, using analytic cross-geometry Gaussian overlaps
with the same normalization/order as the Molden viewer. Both orbital norms are
checked. No assumption of fixed energy ordering or occupied/virtual membership.
An accumulated sign aligns orbital phases for viewer playback and animation export.
Raw Molden files are unchanged. Default minimum |overlap| is 0.5; minimum separation
from the next candidate is 0.1. Ambiguous/weak matches are left unassigned and tracked
playback stops before showing an arbitrary replacement. Users can inspect the score,
change thresholds or choose another anchor. Changing orbital selection disables
tracking. Tracks live in the session and are rebuilt after reopening the application.
Limitations: real MOs, at most 1000 AOs/frame, same atom order, stored orientation.
Large rigid rotations/translations or sparse paths can cause low overlaps. There
is no automatic rotational alignment, subspace mixing or excited-state tracking.
Degenerate subspaces do not define unique individual orbital identities.
